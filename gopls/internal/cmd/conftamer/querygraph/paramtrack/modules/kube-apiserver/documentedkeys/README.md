# Documented config keys: kube-apiserver

This directory holds kube-apiserver's documented config keys, one list per config file. They are meant to be compared
with the keys that the static analysis finds in the code. The format is the one in
`../../prometheus/documentedkeys/README.md` and `../../caddy/documentedkeys/README.md`:
- one `<dotted key>\t<documented type>` per line
- list indices left out
- no `k=v` segments (see "Values that pick the fields that follow" below)

Each list starts at its own file's root, as a paramtrack run rooted at that file's versioned Go type would produce
it. The kind is not a prefix, and `apiVersion`/`kind` are not keys.

Version analyzed: Kubernetes **v1.31.1**, at `/home/emily/go/src/k8s.io/kubernetes` (`835c875ca06`). That is
v1.31.1 plus 3 commits that only touch Dockerfiles. Only git-tracked files were read. Paths below are relative to that
checkout, and `apiserver/` stands for `staging/src/k8s.io/apiserver/`.

## What "the config" is
kube-apiserver has **no main config file**: it has no ComponentConfig and no `--config` flag. It is configured in three ways:
- (a) 157 command-line flags
- (b) about a dozen config files, each named by its own flag
- (c) the API objects it serves

The researcher's scope (decided 2026-11-14) is the six versioned config files in (b) that are listed above.

### Out of scope, with phase-1 sizes
These counts are rough leaf-key counts from the reference pages, not lists.
- **Flags (a):**
  - 157 documented on the generated `kube-apiserver.md` page.
  - Parsed by pflag into `cmd/kube-apiserver/app/options.ServerRunOptions`, which embeds
    `pkg/controlplane/apiserver/options.Options`.
  - Not reloaded.
  - Some are the legacy form of a file in scope: the `--oidc-*` flags for `--authentication-config`, and
    `--authorization-mode` / `--authorization-webhook-*` for `--authorization-config`.
- **API objects (c):**
  - 83 kinds in 23 group/versions, with about 2,600 properties (`api/openapi-spec/swagger.json`).
  - Some of them configure the server itself: webhook configurations, ValidatingAdmissionPolicy, APIService,
    FlowSchema / PriorityLevelConfiguration, CRDs and RBAC.
- **AdmissionConfiguration (`--admission-control-config-file`):**
  - 3 keys of its own: `plugins.{name,path,configuration}`.
  - `configuration`, or the file named by `path`, is opaque bytes. Each plugin decodes them again into its own type,
    chosen by `plugins[].name`:
    - EventRateLimit (4 keys)
    - ResourceQuota (~6)
    - PodTolerationRestriction (~10)
    - PodSecurity (~9)
    - Validating/MutatingAdmissionWebhook (1, a kubeconfig path)
    - ImagePolicyWebhook (5)
    - PodNodeSelector (1 map)
  - It is read by `ReadAdmissionConfiguration` (`apiserver/pkg/admission/config.go:57`).
- **Webhook kubeconfigs:**
  - Named by `--authentication-token-webhook-config-file`, `--authorization-webhook-config-file`,
    `authorizers.webhook.connectionInfo.kubeConfigFile`, `--audit-webhook-config-file`, `WebhookAdmission.kubeConfigFile`
    and ImagePolicyWebhook's `kubeConfigFile`.
  - About 46 keys each (client-go `clientcmd/api/v1.Config`).
  - The admission-webhook kubeconfig matches `users[].name` against webhook hosts.
- **Others:**
  - the ABAC policy (`--authorization-policy-file`, ~8 keys, one JSON object per line)
  - the token CSV (`--token-auth-file`)
  - PEM files
  - the deprecated `--cloud-config` (opaque bytes, unused in-tree in 1.31)

### The six files in scope
"k8s codec" means the following:
- The call is `runtime.Decode(serializer.NewCodecFactory(scheme[, EnableStrict]).UniversalDecoder(), data)`.
- It accepts YAML or JSON. YAML is converted to JSON by `sigs.k8s.io/yaml`.
- It unmarshals with `sigs.k8s.io/json` (`UnmarshalCaseSensitivePreserveInts`, a case-sensitive fork of
  `encoding/json`; `apimachinery/pkg/runtime/serializer/json/json.go:255`).
- It picks the Go type at runtime from `apiVersion`/`kind` (`scheme.New`), applies defaults, and converts to the
  internal type with the generated `zz_generated.conversion.go`.
- Strict means it fails on unknown or duplicate fields.

| File (flag) | Decode target → internal type | Loader, decoder | Reloaded |
|---|---|---|---|
| `--authentication-config` | `apiserver/pkg/apis/apiserver/v1beta1.AuthenticationConfiguration` (or `v1alpha1`) → `apiserver.AuthenticationConfiguration` | `pkg/kubeapiserver/options/authentication.go:847` `loadAuthenticationConfig`, k8s codec, strict | yes, file watch (`authentication.go:727`), except `anonymous` |
| `--authorization-config` | `.../v1beta1.AuthorizationConfiguration` (or `v1alpha1`) | `apiserver/pkg/apis/apiserver/load/load.go:40`, k8s codec, strict | yes (`pkg/kubeapiserver/authorizer/reload.go:183`) |
| `--encryption-provider-config` | `.../v1.EncryptionConfiguration` | `apiserver/pkg/server/options/encryptionconfig/config.go:214` `LoadEncryptionConfig`, k8s codec, strict | only with `--encryption-provider-config-automatic-reload` (polls every minute) |
| `--audit-policy-file` | `apiserver/pkg/apis/audit/v1.Policy` | `apiserver/pkg/audit/policy/reader.go:63`, k8s codec, strict and then a lenient retry | no |
| `--egress-selector-config-file` | **always** `.../v1beta1.EgressSelectorConfiguration` | `apiserver/pkg/server/egressselector/config.go:49`. This is plain `sigs.k8s.io/yaml.Unmarshal` into that struct (not strict; only `kind` is checked), then `cfgScheme.Convert` | no |
| `--tracing-config-file` | `.../v1beta1.TracingConfiguration` (or `v1alpha1`), which embeds component-base `tracing/api/v1.TracingConfiguration` | `apiserver/pkg/server/options/tracing.go:144`, k8s codec `DecodeInto`, not strict | no |

**Which group each kind is decoded under.**
- The `apiserver/pkg/apis/apiserver` versioned packages register two groups (`v1alpha1/register.go`,
  `v1beta1/register.go`):
  - `GroupName = "apiserver.k8s.io"`: **EgressSelectorConfiguration**, and AdmissionConfiguration in v1alpha1.
  - `ConfigGroupName = "apiserver.config.k8s.io"`: **Authentication-, Authorization- and TracingConfiguration**.
  - `v1` has only `apiserver.config.k8s.io`: **EncryptionConfiguration** and AdmissionConfiguration.
- The reference pages are titled with the package's `GroupName` (`apiserver.k8s.io/v1beta1`). They show that group
  as the `apiVersion` of every kind on the page.
- That is right for EgressSelectorConfiguration. Its loader ignores `apiVersion` anyway.
- For the other three kinds the right `apiVersion` is `apiserver.config.k8s.io/v1beta1`. The loaders'
  schemes (`install.Install`) register those kinds only under that group, so `apiserver.k8s.io/v1beta1` would not
  decode.
- Key paths don't depend on the group.

**Which version each list is for.**
- AuthenticationConfiguration and AuthorizationConfiguration: **v1beta1**. It is the beta API, on by default in 1.31
  (`StructuredAuthenticationConfiguration`, `StructuredAuthorizationConfiguration`), and the version the docs'
  examples use.
- EgressSelectorConfiguration: **v1beta1**, because the loader always decodes into v1beta1.
- TracingConfiguration: **v1beta1**, the newer of the two.
- EncryptionConfiguration and audit Policy have only **v1**.
- The v1alpha1 pages give **the same keys and types** for all four files that have two versions. The script prints
  any difference, and it printed none. The only other v1alpha1 kind, AdmissionConfiguration, is out of scope.

**The internal types have no json tags** (`apiserver/pkg/apis/apiserver/types.go`). The code uses them after
loading. A run rooted at the versioned type has to follow the generated conversions, many of which copy with
`unsafe.Pointer` casts, to reach the code that uses the values. The decode target is allocated by `scheme.New`, so
static analysis sees no concrete type at the unmarshal call. The egress selector is the exception. The roots may
need to be given explicitly, as Caddy's `module.py` does with `-extra` roots.

## Format and judgment calls
- **Expansion.** The script starts at the root kind's section and recurses into linked struct sections.
  - List fields add no segment, e.g. `jwt.claimMappings.username.prefix` with `jwt` a list.
  - Embedded members (`(Members of X are embedded into this type.)`) add no segment either. Tracing's v1beta1
    TracingConfiguration embeds component-base's TracingConfiguration.
  - There is no recursion in these types, so no key was cut off.
- **Fields whose name picks the rest** are just distinct field names, with no `k=v`. This applies to EncryptionConfiguration's
  providers (`resources.providers.{aescbc,aesgcm,secretbox,kms,identity}`) and to egress `transport.{tcp,uds}`.
- **Values that pick the fields that follow: no `k=v` segments.** In three places a value picks which sibling
  fields are valid, but the fields are all in one Go struct, decoded the same whatever the value, so the static
  analysis's full keys have no `k=v` there, and the lists match them (the researcher's decision, 2026-11-14, after
  comparing them with the graph's keys). The selector keys are listed as ordinary keys.
  - `authorizers.type` and `authorizers.webhook.*`. The docs say webhook "Must be defined when Type=Webhook / Must
    not be defined when Type!=Webhook". The other types (Node, RBAC, AlwaysAllow, AlwaysDeny) have no fields.
  - `authorizers.webhook.connectionInfo.type` and `...connectionInfo.kubeConfigFile`. The docs say "Required, if
    connectionInfo.Type is KubeConfig", a typo for `KubeConfigFile` (the `type` field's docs list `KubeConfigFile`
    and `InClusterConfig`; `InClusterConfig` has no fields, and isn't allowed in kube-apiserver).
  - `egressSelections.connection.proxyProtocol` and `...connection.transport.*`. The docs say transport "is
    required if ProxyProtocol is HTTPConnect or GRPC", and that GRPC "is not supported with TCP transport". `Direct`
    forbids `transport`, per the validation code (`apiserver/pkg/server/egressselector/config.go:170`), not the docs.
- **Not a `k=v`:** `resources.providers.kms.cachesize` is "only allowed for KMS v1 providers", i.e. for one value of
  the sibling `kms.apiVersion`. It's a single field with the same meaning in both versions, not a choice of
  sub-structure, so it is listed as `resources.providers.kms.cachesize`. `kms.apiVersion` is a real key, not
  TypeMeta, and is listed.
- **Not listed:**
  - `resources.providers.identity`: an empty struct (`identity: {}`) that only selects the no-encryption provider.
    It's a choice with no fields of its own.
  - audit `Policy.metadata`: an `ObjectMeta` "included for interoperability with API infrastructure". It is
    accepted but isn't config, and its fields aren't on the page.
  - `apiVersion`/`kind` of each kind.
- **Placeholders and maps:** none. No field in scope is a map with user-chosen keys. `claimMappings.extra` is a
  list of `{key, valueExpression}`, not a map.
- **Fixed-value strings stay values, not segments:**
  - `egressSelections.name` takes `controlplane`, `etcd` or `cluster`.
  - `rules.level` takes `None`, `Metadata`, `Request` or `RequestResponse`.
  - Neither picks other fields.
- **Feature-gated, but listed:** `anonymous.*` in AuthenticationConfiguration needs the alpha gate
  `AnonymousAuthConfigurableEndpoints`, which is off by default in 1.31. The page doesn't say so.
